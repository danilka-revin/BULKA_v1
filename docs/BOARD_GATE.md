# ЭКРАН ЗАПУСКА: PIN, РОЛИ И ПАНЕЛЬ ПОЛУЧАТЕЛЯ

> Относится к справочному серверу `gui/backend.py` и страницам `gui/gate.html`,
> `gui/main.html`, `gui/user.html`. Рабочая копия интерфейса робота живёт в
> [danilka-revin/Zapret](https://github.com/danilka-revin/Zapret); здесь описано
> поведение именно этого репозитория.

При включении бортового дисплея первым открывается **экран запуска** с
клавиатурой PIN. Код выбирает режим, и человек попадает на нужную страницу:

| PIN | Роль | Что открывается | Что можно |
| :---: | :--- | :--- | :--- |
| **7232** | оператор | киоск `main.html`: двигатели, АКБ, отсек | всё, что умеет бортовой экран, плюс инженерный пульт `/console` |
| **5656** | получатель | панель `user.html` | смотреть общее состояние и открывать/закрывать отсек по PIN |
| — | гость | остаётся на `gate.html` | ничего, кроме просмотра сводки на самом экране запуска |

**PIN отсека — отдельный код** (заводской `2580`, меняется в пульте). Его
спрашивают при открытии и закрытии грузового кейса и в режиме оператора, и в
режиме получателя. Это не код входа на экран: 7232 и 5656 не открывают замок.

## 1. Как устроен вход

```
браузер на борту            сервер gui/backend.py
────────────────            ───────────────────────────────────────────
GET  /gate.html      →      статика, доступна всегда
POST /api/gate       →      PIN → роль, HttpOnly-cookie rus_role (8 ч)
                            неверный PIN: 5 попыток, затем блокировка 30 с
GET  /               →      302: оператор → /main.html, получатель → /user.html
                            без cookie → /gate.html
POST /api/logout     →      cookie снимается, экран возвращается к PIN
```

* Роль хранится **на сервере** (в памяти процесса), а браузер получает только
  случайный токен в cookie `HttpOnly; SameSite=Strict`. Подделать cookie, чтобы
  стать оператором, нельзя: сервер сверяет токен со своей таблицей.
* PIN запуска тоже живёт на сервере. Страница не знает правильных кодов и не
  решает, кого пускать.
* Пять неверных кодов подряд блокируют ввод на 30 с — и верный PIN в это время
  не принимается. Счётчик общий на процесс, а не на вкладку браузера.
* Сессия живёт 8 часов или до нажатия «Сменить пользователя». После выхода
  `main.html` и `user.html` снова закрыты: их отдаёт только сервер с ролью.
* Если браузер не отдаёт cookie (встроенное окно предпросмотра, приватный
  режим, запрет сторонних cookie), сервер принимает тот же токен из адреса
  (`?t=…`) и из заголовка `X-Session`. Код входа при этом остаётся на сервере:
  токен — это случайная строка, а не PIN.

### Что закрыто в режиме получателя

Получатель не может попасть ни на киоск оператора, ни на инженерный пульт:

| Запрос | Ответ сервера в роли `user` |
| :--- | :--- |
| `/main.html`, `/` | 302 → `/user.html` |
| `/index.html`, `/console`, `/console.js`, `/console-core.js`, `/app.js`, `/vision.js`, `/styles.css` | 302 → `/gate.html` |
| `POST /api/lock/pin` | 403 «в режиме получателя PIN не меняется» |
| `POST /api/lock/close` без PIN | 403 «нужен PIN отсека» |
| `POST /api/lock/open` с PIN | 200, отсек открывается |
| `GET /api/state`, `/api/audit` | 200, только чтение |

На панели получателя нет ни настроек, ни калибровок, ни ссылок на служебные
страницы — только состояние, характеристики робота и журнал последних операций.

## 2. Экран запуска (`gate.html`)

* крупная клавиатура 3 × 4: цифры, «Стереть», «Войти»; после четвёртой цифры
  код отправляется сам;
* ввод с физической клавиатуры: цифры, Backspace, Enter;
* точки-индикаторы не показывают цифры, только их количество;
* ошибка — тряска панели и сообщение; при блокировке идёт обратный отсчёт;
* слева — живые, но обезличенные данные: есть ли связь, закрыт ли отсек, заряд
  АКБ. Этого достаточно, чтобы понять, что борт отвечает, и не хватает, чтобы
  управлять роботом;
* если сессия уже есть, экран не запирает: он предлагает «Продолжить как
  оператор / получатель»;
* на демо-стенде внизу показаны коды `7232` и `5656`. В изделии эту строку
  нужно убрать — она часть демонстрации, а не интерфейса.

## 3. Панель получателя (`user.html`)

| Блок | Содержимое |
| :--- | :--- |
| **Грузовой отсек** | «Открыть отсек» / «Закрыть отсек»; обе операции по PIN отсека; масса груза, размеры отсека |
| **Аккумулятор** | заряд в процентах и полосой, напряжение, ток, запас хода |
| **Показатели** | скорость, маршрут, время в работе, состояние замка |
| **О роботе** | габариты, масса, грузоподъёмность, скорость, привод, батарея — справочно |
| **Последние операции** | вход на экран, удачные и неудачные вводы PIN, время |
| **Шапка** | связь с бортом, режим, часы, «Сменить пользователя» |

Данные обновляются раз в 1,2 с запросом `GET /api/state`; журнал — раз в 8 с.
Если сервер не ответил, панель честно пишет «нет связи» и не показывает
выдуманные числа.

## 4. Запуск

```bash
python3 gui/backend.py                     # 0.0.0.0:8080, сам окон не открывает
python3 gui/backend.py --kiosk             # + браузер на дисплее: /gate.html
```

На борту экран открывает `deploy/systemd/display.sh` (сервис
`rus-slam-display.service`) — по умолчанию `http://127.0.0.1:8080/gate.html`.
Проверить руками:

1. открыть `http://127.0.0.1:8080/` — должен появиться экран с PIN;
2. набрать `5656` — откроется панель получателя без служебных разделов;
3. нажать «Сменить пользователя» и набрать `7232` — откроется киоск оператора;
4. в киоске открыть отсек кодом `2580`.

Коды входа можно переопределить при запуске:

```bash
python3 gui/backend.py --operator-pin 1111 --user-pin 2222
```

PIN отсека задаётся отдельно: `--pin 2580` (заводской) и меняется в пульте.

## 5. Безопасность: что важно знать

* **Это экранная блокировка, а не полноценная аутентификация.** Она не даёт
  получателю случайно попасть в настройки, но не защищает от человека с
  физическим доступом к борту и отладчиком.
* API `GET /api/state`, `/api/audit`, `/api/health` и операции с замком
  по-прежнему доступны без cookie — так работают нативный экран
  `native_display.py` и удалённая диагностика. Если борт выходит в общую сеть,
  закройте API на уровне обратного прокси или firewall.
* `/api/health` отдаёт `pinDefault` — заводской PIN отсека. В изделии это поле
  нужно убрать вместе с демо-подсказкой на экране запуска.
* Токен в `?t=…` попадает в историю браузера. Для киоска на борту это
  приемлемо; если борт смотрит человек со своим браузером, полагайтесь на
  cookie и не публикуйте ссылку с токеном.
* Смена PIN отсека разрешена только роли `operator`; получатель получает 403.
* Все входы и попытки ввода пишутся в журнал с хеш-цепочкой
  (`GET /api/audit`, `integrity.ok`).
